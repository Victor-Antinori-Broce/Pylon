## Arquitectura

### Diseño de Estados (First-Class Entities)
- Los estados son ENTIDADES, no enums
- Cada proyecto define sus propios estados
- Cada estado tiene: `name`, `color`, `group` (backlog/todo/in-progress/done)
- Kanban renderiza columnas dinámicamente desde `agile_states`

### Key Format (Auto-generado)
- Formato: `{identifier}-{counter}` (ej: "PROJ-123")
- Counter por proyecto, atómico (db.transaction)
- Índice único: `UNIQUE(projectId, identifier, keyCounter)`

### Cycles vs Modules
- **Cycles**: Tiempo (sprints)
  - Fechas: `startsAt`, `endsAt`
  - Issues se asignan a cycles
- **Modules**: Scope (épicas)
  - Agrupación lógica de issues
  - Relación many-to-many via `agile_module_issues`

### AI Safety Pattern (Intakes)
- `agile_submit_intake`: La IA NUNCA escribe directamente en issues
- Crea intake con status='pending'
- Humano aprueba via `/intakes/:id/approve` con transacción atómica
- Protección contra escritura accidental

## API Endpoints (15 total)

| Método | Ruta | Descripción |
|--------|------|-------------|
| GET | `/:projectId/issues` | Lista issues con estados |
| POST | `/:projectId/issues` | Crear issue (auto-key) |
| GET | `/:projectId/issues/:id` | Detalle issue |
| PUT | `/:projectId/issues/:id` | Actualizar issue |
| DELETE | `/:projectId/issues/:id` | Soft delete issue |
| POST | `/:projectId/issues/:id/transition` | Cambiar estado |
| GET | `/:projectId/cycles/:cycleId/issues` | Issues del sprint |
| GET | `/:projectId/modules/:moduleId/issues` | Issues de módulo |
| GET | `/:projectId/estimates` | Estimaciones del proyecto |
| GET | `/:projectId/estimates/:estimateId` | Detalle estimación |
| GET | `/intakes` | Lista intakes |
| GET | `/intakes/:id` | Detalle intake |
| POST | `/intakes` | Crear intake (sugerencia IA) |
| POST | `/intakes/:id/approve` | Aprobar intake (transacción) |
| DELETE | `/intakes/:id` | Rechazar/borrar intake |

## MCP Tools

### agile_read_board (Read-Only)
```typescript
Input:  { projectId: string }
Output: { 
  states: Array<{id, name, color, group, order}>,
  issuesByState: Record<stateId, Issue[]>,
  totalIssues,
  project: { id, name, identifier }
}
```

### agile_submit_intake (Write-Controlled)
```typescript
Input:  { projectId, title, description, payload? }
Output: { success: true, intake: { id, status: 'pending' } }

// NUNCA escribe a agile_issues directamente

```
